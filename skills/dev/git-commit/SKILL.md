# Git Commit スキル

## 哲学

- **小さく、意味のある単位でコミットする**。レビューしやすく、デグレの追跡が容易になる。
- **理由まで記録する**。未来の自分やレビュアーへの贈り物。
- **AIが面倒な部分を担う**。メッセージ考案・理由の言語化はClaudeが行う。

## コミットメッセージの書式

type: 何をしたか（体言止め）

なぜそうしたか。ユーザーから得た文脈をそのまま使う。

typeはConventional Commitsに従う：feat / fix / docs / style / refactor / test / chore / perf / revert

理由がない・自明な場合は1行目だけでよい。

## 実行フロー

1. `git status && git diff` で変更を把握する
2. `git add .` は使わない。ファイル単位またはハンク単位でstagingする
3. バイナリはテキストと別コミットにする
4. `git commit -m` で実行する
5. `git log --oneline -5` で確認する

## 吸収（amend / rebase）

「直前のコミットの続き」に見える変更は新しいコミットを作らず吸収させる。
push前のみ使用可。push済みのコミットには使わない。

## Claudeが確認するタイミング

- 変更に複数の意図が混在している場合
- 変更が直前のコミットへの補足に見える場合
- バイナリとテキストが混在している場合
