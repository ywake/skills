# html-wireframe — ブラウザで触れる低忠実度ワイヤー

## 概要

画面設計を「**ブラウザで開けてクリック遷移できる低忠実度の HTML ワイヤーフレーム**」＋「散文の `screens.md`」として残す手法。
配色やタイポは後回しにし、**構造・要素の有無・操作フロー**だけを早く固める。図ツールも画像も使わず、単一HTML（Tailwind CDN）なので作成も共有も軽い。

**中核原則**: ワイヤーは「触って流れを検証する道具」。静的な絵や散文の説明ではなく、実際にクリックして画面遷移を試せる状態にする。HTML を選ぶのはそのためで、デザインツールを開かずにブラウザだけで完結し、レビュアーにはファイルを1つ渡せば済む。

Penpot 上に成果物を作る必要があるとき（デザイナーが続きを引き取る、Penpot でコメントレビューする、PDF にして先方に出す）は `penpot-wireframe` の領分。

## いつ使うか

- 実装前に画面構成・画面遷移・状態バリエーションを固めたいとき
- 「画面設計」「ワイヤー」「モック」「UIのたたき台」を求められたとき
- 既存UIの改修案を、触れる形でレビューに出したいとき
- レビュアーに「開いて触れるもの」を1ファイル渡したいとき（デザインツールの共有設定もアカウントも要らない）

**使わない**:
- 振る舞い・ロジックの仕様そのもの（それは spec 側に書く。ここは「見た目・操作」に絞る）
- 成果物が Penpot ファイル上にあることが要件のとき（→ `penpot-wireframe`）

## 成果物（`docs/3_design/` 等に置く）

| ファイル | 役割 |
| --- | --- |
| `screens.md` | 画面一覧（役割＋仕様リンクの表）／遷移図（mermaid）／状態バリエーション／**未確定**セクション |
| `wireframes/index.html` | 全ワイヤーへのリンク一覧（入口） |
| `wireframes/NN-画面-状態.html` | 1画面1状態のワイヤー。相互リンクでクリック遷移 |
| `wireframes/assets/shell.js` | 複数画面に出る共通部分（ヘッダ・モーダル外枠・深リンク）の一元定義 |

テンプレは [templates/](templates/) にある。複製して埋める:
- [templates/screens.md](templates/screens.md)
- [templates/index.html](templates/index.html)
- [templates/screen.html](templates/screen.html) — **デスクトップ/Web 向け**雛形（サイドナビ＋本体の2ペイン、1280px 枠）
- [templates/screen-phone.html](templates/screen-phone.html) — **モバイル向け**雛形（下部タブ＋縦1カラム、375px 枠）
- [templates/shell.js](templates/shell.js) — 共通シェル。`wireframes/assets/shell.js` にコピーし、ナビの builder を案件に合わせて書き換える（→「共通部分の扱い」節）

検証スクリプトはコピー不要。スキル内から直接実行する:
- [scripts/check_tags.py](scripts/check_tags.py) — タグの開閉バランス検査（→ 手順7）

案件の対象ビューポートに合う方を複製する。枠クラスを替えるだけでなくレイアウトごと変わるため、phone⇄desktop は別雛形を使い分ける。

## 枠の骨格（W×H 固定・枠内スクロール）

デバイス枠は **幅も高さも固定した箱**。枠の中身が増減しても枠のサイズは変えない（＝実機の見え方を保つ）。この骨格を崩すと、枠が中身なりに小さく/縦長に伸縮してワイヤーとして読めなくなる。テンプレ複製でもプロンプトから書き起こすときでも、必ずこの形にする:

```html
<!-- 枠 = W×H 固定の箱。クラスで寸法を与え overflow-hidden で外にはみ出させない -->
<style>.device-desktop{ width:1280px; height:800px; }</style>
<div class="device-desktop bg-white border overflow-hidden flex flex-col">
  <header class="shrink-0 …">…固定ヘッダ/ナビ…</header>
  <!-- 本体だけがスクロール。中身が枠より長ければ枠の中でスクロールする -->
  <main class="flex-1 overflow-y-auto …">…可変コンテンツ…</main>
  <footer class="shrink-0 …">…固定フッタ…</footer>
</div>
```

- 寸法は **width と height の両方** を必ず与える（width だけにしない）。phone 375×760 / tablet 768×1024 / desktop 1280×800。
- 枠そのものに `flex-1` や `w-full`、`items-start`＋高さ未指定を使わない（中身任せで潰れる/伸びる原因）。横並びの親に `items-stretch` は付けず、枠は自分の固定サイズを保つ。
- ヘッダ/ナビ/フッタは `shrink-0`、スクロールさせたい本体だけ `flex-1 overflow-y-auto`。

## 手順

1. **画面と遷移を洗い出す** → `screens.md` に画面一覧表（役割＋仕様リンク）と mermaid の遷移図を書く。
2. **各画面の状態を列挙** → 空 / 読込中 / 失敗 / フォールバック / 権限なし 等。`screens.md` の「状態バリエーション」に明記。状態は粒度で扱いを変える（下表）。
3. **ワイヤーを作る** → `templates/screen.html` を複製し `wireframes/NN-画面-状態.html` に。デバイス枠を選び、レイアウトと注釈幅も枠に合わせる。同一画面で複数の画面レベル状態を見比べるときは `<section>` を複製して横並びにする。複数画面に出る部分は最初から `assets/shell.js` へ（→「共通部分の扱い」節）。
4. **クリック遷移を張る** → `index.html` から各画面へ、画面間も `href`/`onclick` で実際に遷移できるようにする。
5. **低忠実度を保つ** → 配色・タイポは「未確定」のまま構造だけ。決めたら `screens.md` と各HTMLの説明文に反映する。
6. **spec と相互リンク** → 各ワイヤーから対応する仕様ファイルへリンク。振る舞いの正は spec、ワイヤーは見た目・操作。
7. **検証する** → [scripts/check_tags.py](scripts/check_tags.py) でタグの開閉バランスを機械チェックし、ブラウザで開いて目視する。HTML はタグの対応が壊れてもエラーを出さない — 閉じタグを間違えた要素が後続の兄弟を飲み込み、レイアウトが黙って崩れる（実例: `<a>` を `</button>` で閉じ、サイドバー全体が白い箱に飲まれた）。shell.js に抜き出した markup は JS のテンプレート文字列になり、エディタのタグ対応チェックも効かないため、チェックは `assets/*.js` も対象に掛ける。

## アイコン

素の Tailwind にアイコンは無い。OS 依存グリフ（SF Symbols 等）は他環境で描画されないので使わない。テンプレは **Lucide 公式（バニラJS）** を CDN 1本で読み込み済み:

```html
<script src="https://cdn.jsdelivr.net/npm/lucide@1.33.0/dist/umd/lucide.min.js"></script>
<style>
  /* lucide の既定は 24px 固定で font-size を無視する。Tailwind の text-* に追従させ、
     本文中に混ざったアイコンが単独で改行されないよう inline とベースラインも与える */
  svg.lucide { width: 1em; height: 1em; display: inline-block; vertical-align: -0.125em; }
</style>

<i data-lucide="settings" class="text-lg text-neutral-500"></i>

<script>lucide.createIcons();</script><!-- body 末尾で1回。shell.js を読むページでは不要（render が呼ぶ） -->
```

`lucide.createIcons()` が `<i data-lucide="...">` をインライン SVG に置き換える（class は SVG にマージされる）。この方式の利点は2つ: **スクリプト1本に全アイコンが入っていて実行時に外部へ取りに行かない**ため、社内プロキシやオフラインでも壊れない（Web コンポーネント型のアイコンローダーは実行時に API からデータを取るものがあり、そこだけ全滅する）。**インライン SVG なので `fill` 等の SVG 属性がそのまま効き**、塗りつぶし表現（登録済みブックマーク等の ON 状態）は `fill="currentColor"` で作れる（shadow DOM 描画のローダーではこれができない）。バージョンは固定する（`@latest` は将来の破壊的変更で壊れる）。

**Lucide の落とし穴**（サイズ・改行は上記 CSS で対処済み。残り2つは書き方の問題）:
- アイコンの**差し替え**には要素の作り直しが要る（`setAttribute` では変わらない）→ 開閉を示す chevron は差し替えず、`chevron-down` に `-rotate-90` を付け外しして向きを変える
- ON/OFF の見た目は `svg.setAttribute('fill', on ? 'currentColor' : 'none')` で切り替える

## 共通部分の扱い — 複数画面に出るものは最初から共通シェルへ

**2画面以上に出てくる部分**（ヘッダ・ナビ・バナー・モーダル外枠・確認ダイアログ）は、最初から `wireframes/assets/shell.js` に置く（雛形: [templates/shell.js](templates/shell.js)）。2画面目で同じ markup を書きそうになったら、それはシェル行き。

コピー運用にしない理由: 複製は**黙って**分岐する（実例: ヘッダ12コピーがいつの間にか5変種に分岐）。分岐すると読み手に「画面ごとの仕様差」なのか「描き落とし」なのか区別できなくなり、後から集約するには全ページの移行＋回帰検証が要って高くつく。プレースホルダ1行を置くほうがコピーより安い。ワイヤーは元々 onclick で動く JS 前提の作りなので、共通部分を JS 描画にしても依存の種類は増えない。classic script なので `file://` で直接開いても動く（zip で渡してダブルクリックされる前提を壊さない）。

各ページは中身を書かず、プレースホルダだけを置く:

```html
<div data-wf="header" data-variant="admin"></div>   <!-- 中身を持たない → 丸ごと生成 -->
<div data-wf="modal" data-id="editForm" data-title="機種の編集" data-width="520">
  …フォームのフィールド（画面固有なので HTML に残す）…
</div>                                              <!-- 中身が画面固有 → 外枠だけ包む -->
```

- **共通化するのは骨格が一致している層だけ**。ヘッダ・バナー・確認ダイアログは全体を、モーダルは外枠（オーバーレイ＋パネル＋見出し行）だけを共通化し、フォームのフィールド構成は画面ごとに別物なので HTML に残す。迷ったら実物同士を並べて一致率を見てから決める — 一致しないものを無理に共通化すると、汎用フォームビルダーのような複製より複雑な代物になる。
- **モーダルを別ページに切り出さない**。モーダルはオーバーレイなので、別ページ化すると背後の画面を丸ごと複製することになる（実測: 4画面で +4,100行）。同一フレーム内に置き、URL ハッシュ（`08-manuals.html#csvImport`）で直接開けるようにすれば「1URL=1状態」の利点は複製ゼロで得られる（shell.js の深リンクが対応）。
- **操作要素は全ページで同じ挙動にする**。同じ見た目のボタンが「この画面では開くが、あの画面では無反応」だと、仕様差なのか描き落としなのか読み手に区別できない。さらに悪いのは動くように見せて `location.href` で別画面に飛ばす偽装（フォームがある画面へ逃がす等）。共通シェルに置けば自然に全ページで動く。ダミーデータが要るもの（ページネーション等）は無理に動かさず、**全ページ一貫して無反応**に揃える。

## 守ること（rationale つき）

- **低忠実度の規律**: 早い段階で色・フォントを決めると、構造の議論が止まり手戻りが増える。「未確定」と書いて構造に集中する。決めた項目だけ明示的に「確定」と書く。
- **状態を網羅**: 正常系だけのワイヤーは後で空・失敗で破綻する。各画面の異常系を最初に列挙し、別フレーム or 同一フレーム内の切替で見せる。
- **クリックできること（枠内で歩ける）**: 流れの良し悪しは触らないと分からない。すべての遷移を、それが起きる要素の近くをクリックして辿れるようにする（`onclick`/`href`、パラメータは `URLSearchParams` で簡易に渡す）。リンクを注釈にだけ置くのは導線にならない — レビュアーは注釈を下まで読まない。
- **ユーザー操作なしに起きる遷移も歩けるように**: 生成完了・タイムアウト・自動リダイレクトには押せる本物の UI が無いため、放置すると導線が注釈へ流れて画面が行き止まりになる。破線＋monospace のチップを発生源の直下（枠内、ただしバブル等の部品の外）に置き、チップ自身に「ワイヤー操作」と名乗らせて仕様上の部品と区別する:

  ```html
  <a href="04-done.html" title="生成が完了した場合の画面へ"
     class="note text-[11px] border border-dashed border-neutral-400 rounded-full px-2.5 py-1">
    生成完了 → 04 完了画面
  </a>
  ```
- **spec と分離**: ワイヤーに振る舞いの詳細を書き込むと、どちらが正か分からなくなる。ワイヤー＝見た目・操作、spec＝振る舞い、で相互リンクする。「未確定」も同じ線で分ける — ワイヤー側に書いてよいのは「**このワイヤーで**決めていないこと」（低忠実度・配色未定といった描き方の宣言）だけで、**仕様として**決まっていないことは spec の未確定リストに置く。
- **デバイス枠の明示**: ビューポート（phone 375×760 / tablet 768×1024 / desktop 1280×800 等）を **W×H 固定の箱** にして対象サイズ前提でレイアウトを見る。骨格（固定寸法＋枠内スクロール）は「枠の骨格」節の形を必ず守る。
- **注釈は説明文にしない**: フレーム横の注釈に置いてよいのは、文章に置き換えられない**操作**（状態切替のボタン等）だけ。決めたこと・出し分けルール・仕様の未確定も含め、文章で書けることはすべて spec に書き、ワイヤーからはリンクする。注釈に文章を書き始めると、画面間でコピペされて増殖し、更新規律のない「二つ目の仕様書」になる（実例: 13画面でのべ316行に達し、32%が画面間の複製、一部の仕様がワイヤーにしか無い状態になった）。記号の意味（破線・ハッチ・非活性が何か）も注釈へ逃がさず、図中の要素自身に短くラベルを付ける — 「ワイヤー操作」チップが自ら名乗るのと同じ形。
- **状態の粒度で扱いを分ける**: **画面レベル状態**（空 / 読込中 / 失敗 / 権限なし）は別フレーム（別HTML）に分ける。**要素レベル状態**（入力エラー / モーダル / トースト / インライン展開）は遷移を伴わないので、同一フレーム内で併記するか JS で開閉して見せる。「異常系＝必ず別フレーム」と機械的に分けない。
- **共通ナビ/ヘッダ**: 2画面以上に出るものは最初から shell.js に置く（→「共通部分の扱い」節）。コピーは黙って分岐する。

## よくある失敗

| 失敗 | 直し方 |
| --- | --- |
| いきなり高忠実度（色・影・フォント作り込み） | 構造と要素の有無だけ。色は neutral 系のまま「未確定」と明記 |
| 正常系1枚だけ | 状態を列挙し、空/読込中/失敗を別フレームに |
| 静的な絵・箇条書き説明だけ | 単一HTMLにして相互リンクでクリック遷移可能に |
| 仕様の文章をワイヤーに書き込む | 振る舞いは spec に。ワイヤーからはリンクするだけ |
| 注釈に出し分けルール・決定・未確定を書き溜め、二つ目の仕様書になる | 注釈は操作（状態切替）だけ。文章で書けることは spec へ移し、ワイヤーからリンク |
| 自動で起きる遷移（完了・失敗・タイムアウト）が枠内から辿れない | 破線＋monospace の「ワイヤー操作」チップを発生源の直下に置く |
| ファイル名がバラバラで一覧できない | `NN-画面-状態.html` 連番＋`index.html` で入口を1つに |
| 画面フレームが小さい／高さが中身依存で可変（枠が伸縮する） | `.device-*` で **W×H を固定** し `overflow-hidden`。本体は内側 `flex-1 overflow-y-auto` で枠内スクロール。枠に `flex-1`/`w-full`/`items-start`＋高さ未指定を使わない（→「枠の骨格」節） |
| デバイス枠クラスだけ替えてレイアウトは縦積みのまま | 枠に合わせてレイアウト（phone=縦1カラム / desktop=サイドナビ＋本体・テーブル）と注釈幅も変える |
| 入力エラーやモーダルを別フレームに切り出して画面が増殖 | 要素レベル状態は同一フレーム内で（前述の粒度ルール）。直接見せたい状態は URL ハッシュで開く |
| 共通ヘッダを各ページにコピーして、画面ごとに微妙に違ってくる | 複数画面に出るものは最初から shell.js へ（→「共通部分の扱い」節） |
| ボタンが一部の画面でだけ動く／別画面へ飛ばして誤魔化す | 操作要素は全画面で同じ挙動に。共通シェルに置くか、全画面一貫の無反応に揃える |
| 閉じタグの取り違えでレイアウトが黙って崩れる（HTML はエラーを出さない） | 編集後に check_tags.py（`assets/*.js` も対象）＋ブラウザ目視（手順7） |

## 配置と移植

- このスキルはリポジトリ内 `.claude/skills/html-wireframe/` に置く。
- 他PJで使うときは、このディレクトリごとコピーするか `~/.claude/skills/` に置けば横断で使える。テンプレは媒体非依存（素のHTML+Tailwind CDN）なのでどのスタックのPJでもそのまま動く。
